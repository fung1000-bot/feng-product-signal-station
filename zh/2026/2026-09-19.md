# 枫的产品信号站 - 2026-09-19

## 今日主判断

相比再做一个宽泛的 AI 应用生成器，更值得验证的是“帮助 AI 编程用户看住、保存和复盘 AI Agent 工作过程”的轻量工具：需求明确、目标用户集中，也能直接转化为 AI 编程实战内容。

## 今日最值得做的一个方向

**项目名：** AI 编程 Agent 工作保护层

**面向谁：** 经常使用 Claude Code、Codex、Gemini、Aider、Copilot 等 AI 编程 Agent 的个人开发者和小团队。

**解决什么具体问题：** AI Agent 执行任务时，用户难以看清它正在做什么；对话或上下文中断后，容易丢失工作；多个 Agent 并行时，也缺少统一的任务、检查点和操作记录。

**使用场景：**
- 开始一个 AI 编程任务前，保存目标、约束和当前项目状态。
- Agent 执行过程中查看文件读写、终端命令和任务进度。
- 上下文接近上限时保存关键内容。
- 对高风险方案进行分支试验，不破坏原来的工作线程。
- 任务结束后导出过程，作为复盘或教程素材。

**为什么今天：** TrustMRR 同时出现了面向 AI 编程用户的两类小工具：Termi Protocol 处理 Agent 的可视化、检查点和团队协作；ClaudeKit 处理上下文截止、提示词保存、Token 计数和对话导出。这说明“AI 编程本身之外的工作保护和过程管理”已经出现可识别的付费需求，而不是纯粹的概念机会。[Termi Protocol](https://trustmrr.com/startup/termi-protocol)；[ClaudeKit](https://trustmrr.com/startup/claudekit-1)

**为什么适合枫：** 目标用户与 AI 编程学习者、个人开发者高度重合；可以先做浏览器扩展、桌面小工具或本地 CLI，不需要囤货、物流或大额前置投入；开发过程本身还能产出“我用 AI 做一个 AI 编程工具”的内容。

**2 小时验证动作：**
1. 只做一个最小闭环：记录一次 AI 编程会话的目标、关键提示词、终端命令和最终结果。
2. 增加一个“上下文即将失控”的手动保存按钮，不先做自动集成。
3. 找 5 名 AI 编程用户访谈或发帖测试，询问他们最近一次丢失上下文、误改代码或无法复盘 Agent 行为的经历。
4. 用一个落地页测试三个卖点：防止丢上下文、可回溯 Agent 操作、支持分支试验。

**验证成功标准：**
- 至少 3/5 名目标用户能讲出近期发生过的具体问题。
- 至少 2 人愿意实际导入一次自己的 AI 编程会话。
- 至少 1 人愿意留下联系方式或接受付费测试。
- 用户最强反馈集中在“保护工作过程”，而不是泛泛的 Agent 可视化。

**周末能扩成什么：**
- 会话与项目级检查点。
- 风险操作前的自动分支。
- Token 和上下文使用量提示。
- Agent 命令、文件变更和结果摘要。
- 面向学习者的“AI 编程过程回放”和教程导出。
- 支持多个 Agent 的任务面板。

## 今日 Top 3 信号

### 信号 1

**信号类型：** 产品案例

**白话说：** AI 编程工具的机会不只在“让 Agent 写更多代码”，也在于让用户看得见过程、保住成果、控制风险。Termi Protocol 把多个 AI Agent 放进一个可视化桌面环境，强调任务、检查点、记忆和实际终端操作。

**证据：**
- 来源 A：[TrustMRR：Termi Protocol](https://trustmrr.com/startup/termi-protocol)——产品描述为面向 Claude Code、Codex、Gemini、Aider、Copilot 等 Agent 的桌面控制室；公开资料显示收入为 $61，售价为 $2.5k。
- 来源 B：[TrustMRR：ClaudeKit](https://trustmrr.com/startup/claudekit-1)——产品围绕 Claude.ai 的上下文截止、分支、提示词保存、Token 计数和对话导出；公开资料显示收入为 $179，售价为 $1k。

**产品理解卡：**
- **Termi Protocol**
  - 它是什么：AI 编程 Agent 的可视化控制室。
  - 目标用户：AI coding agent users。
  - 解决的痛点：看不见 Agent 在做什么、工作容易丢失、Agent 可能偏离目标。
  - 核心功能或交付：桌面应用；Agent 运行在 3D 房间中，具备任务、检查点、记忆和团队协作能力。
  - 典型使用场景：公开证据未说明。
  - 已知商业数据：TrustMRR 公开资料显示收入 $61、售价 $2.5k、倍数 3.4x；[原始链接](https://trustmrr.com/startup/termi-protocol)。
  - 证据边界：公开资料没有说明活跃用户、留存、付费用户数量及收入时间口径。

- **ClaudeKit**
  - 它是什么：Claude.ai 的工作保护层。
  - 目标用户：Claude.ai power users。
  - 解决的痛点：避免 Claude 会话因上下文截止而丢失工作。
  - 核心功能或交付：截止提醒、对话分支、提示词保存、Token 计数、聊天导出。
  - 典型使用场景：公开证据未说明。
  - 已知商业数据：TrustMRR 公开资料显示收入 $179、售价 $1k、倍数 0.5x；[原始链接](https://trustmrr.com/startup/claudekit-1)。
  - 证据边界：公开资料没有说明用户规模、收入持续时间及具体获客渠道。

**为什么值得关注：** 两个产品都没有试图重新定义 AI 编程，而是在 Agent 工作流中解决“丢失、失控、不可回溯”等具体问题。这样的切口更适合一人先做窄 MVP。

**对枫的启发：** 产品机会和内容选题都成立：可以做“我给 AI 编程 Agent 加了一个撤销键”“AI 写代码最容易丢的不是代码，而是上下文”等实操内容。

**反向证据：** 两个案例来自同一个市场数据库，不是独立的多源验证；收入数字较小或口径未知，不能据此证明市场已经足够大。用户也可能通过 Git、IDE 历史记录、手动复制提示词等方式解决问题。

### 信号 2

**信号类型：** 产品案例

**白话说：** TrustMRR 上的多个 AI 产品都把复杂任务压缩成“输入一个需求，直接得到可交付结果”：电子书、学习资料、视频、音乐或完整应用。这类产品的共同机会是把生成能力包装成明确的结果，而不是单独售卖模型调用。

**证据：**
- [TrustMRR：aiebooks.store](https://trustmrr.com/startup/aiebooks-store)——根据请求生成带图片、格式完整、可下载为 PDF 或 EPUB 的电子书；公开资料显示收入 $115、售价 $6k。
- [TrustMRR：CogniGuide](https://trustmrr.com/startup/cogniguide)——把笔记转成思维导图、闪卡和测验；公开资料显示收入 $680、售价 $30k。
- [TrustMRR：Cliptude](https://trustmrr.com/startup/cliptude)——自动研究、写作并剪辑纪录片式视频；公开资料显示收入 $6.4k、售价 $89k。

**产品理解卡：**
- **aiebooks.store**
  - 它是什么：AI 电子书生成工具。
  - 目标用户：Influencers、Ecommerce、Educators。
  - 解决的痛点：用电子书获取营销线索，以及制作电商数字产品。
  - 核心功能或交付：生成带图片、格式完整的电子书，并即时下载 PDF 或 EPUB。
  - 典型使用场景：公开证据未说明。
  - 已知商业数据：收入 $115、售价 $6k、倍数 4.4x；[原始链接](https://trustmrr.com/startup/aiebooks-store)。
  - 证据边界：公开资料没有说明转化率、用户规模和内容质量控制方式。

- **CogniGuide**
  - 它是什么：把学习材料转成学习辅助资料的 AI SaaS。
  - 目标用户：学生、学习者和教师。
  - 解决的痛点：减少把密集课程材料整理成复习资料的时间。
  - 核心功能或交付：从笔记和学习材料生成思维导图、闪卡和测验。
  - 典型使用场景：公开证据未说明。
  - 已知商业数据：收入 $680、售价 $30k、倍数 3.7x；公开资料还提到 50,000+ 注册用户和 SEO 流量，但这些均来自 TrustMRR 产品资料；[原始链接](https://trustmrr.com/startup/cogniguide)。
  - 证据边界：公开资料没有说明注册用户到付费用户的转化，也没有说明中文市场适配成本。

- **Cliptude**
  - 它是什么：AI 纪录片视频制作工具。
  - 目标用户：YouTube、TikTok、Instagram 创作者。
  - 解决的痛点：减少研究、写稿、剪辑和复杂动效所需的时间。
  - 核心功能或交付：研究、脚本、素材、动态图形、地图和配音等视频生产环节。
  - 典型使用场景：公开证据未说明。
  - 已知商业数据：收入 $6.4k、售价 $89k、倍数 1.2x；[原始链接](https://trustmrr.com/startup/cliptude)。
  - 证据边界：公开资料没有说明视频生成质量、版权处理和客户留存。

**为什么值得关注：** 这组产品提示一个适合内容获客的表达方式：不要讲“AI 能做什么”，而要讲“给定一种输入，几分钟后拿到什么成品”。这能直接转成中文 AI 编程实战选题。

**对枫的启发：**
- 内容选题： “我把一篇课程笔记做成闪卡和测验”“我用 AI 做一个可下载的电子书生成器”。
- 产品机会：面向中文 AI 编程学习者，做“课程/文章 → 练习题、项目任务和复盘卡片”的窄工具。
- 验证方式：先支持 Markdown 或网页文本输入，输出一套可复制的学习任务，不必一开始做完整教育平台。

**反向证据：** 生成内容已经高度同质化，用户可能直接使用通用大模型；CogniGuide 的 SEO 和用户规模未证明可以复制到中文市场；Cliptude 等产品还涉及素材版权、模型成本和长内容质量问题。

### 信号 3

**信号类型：** 技术趋势

**白话说：** AI 视频生成正在从“单次生成素材”进入品牌营销和线下活动场景。Marc Lou 的公开内容显示，他获得 Higgsfield 的 API credits，用 AI 模型如 Seedance 制作营销视频，并把个人品牌曝光、活动赞助和产品制作结合起来。

**证据：**
- [Marc Lou：AI 营销视频与赞助案例](https://x.com/marclou/status/2100923868257169808)——公开内容提到 Higgsfield 提供 $30,000 API credits，并用于制作带 AI 模型视频的营销内容。
- [Marc Lou：活动观众票与退款机制](https://x.com/marclou/status/2100897873823228064)——公开内容显示，他为土耳其伊兹密尔的赛事提供 $10 观众票，并承诺凭票据退款，说明个人品牌、线下活动和产品传播可以被组合设计。

**产品理解卡：** 不适用。

**为什么值得关注：** 这不是单纯的“AI 视频工具更新”，而是一个可借鉴的获客结构：用一个有传播性的活动或故事制造注意力，再把 AI 产品制作过程嵌入其中。对于还没有稳定选题来源的人，比泛泛介绍模型参数更容易形成内容钩子。

**对枫的启发：**
- 产品机会：暂不建议直接做视频生成器；可以做面向 AI 编程学习者的“产品挑战记录器”，把构建过程、结果和传播素材自动整理成一篇小红书或公众号草稿。
- 内容选题： “一个 AI 产品如何把开发过程变成营销素材”“不要只展示 Demo，给你的 AI 产品设计一个可传播的验证挑战”。

**反向证据：** 该案例主要是单个创作者的公开动态，不足以证明普通个人能拿到同等 API 额度或复制相同传播效果；公开证据也没有说明最终产品的用户数、收入或转化结果。

## 机会拆解

- **痛点：** AI 编程用户在 Agent 工作过程中容易丢上下文、误改文件、无法回溯，也难以把一次成功过程沉淀成教程。
- **明确买家：** 高频使用 AI 编程 Agent 的个人开发者、独立开发者、AI 编程学习者和小团队。
- **已有替代：** Git 历史、IDE 本地历史、手动复制提示词、聊天导出、终端录屏和现有 Agent 工具自身的记忆功能。
- **小产品入口：** 先做“会话检查点 + 提示词/命令/结果记录 + Markdown 导出”，不接管 Agent 执行，也不做完整桌面控制室。
- **可验证数据：**
  - 5 名目标用户中，能否找到 3 个近期真实案例。
  - 是否有用户愿意导入一次真实会话。
  - 用户最愿意付费的是防丢上下文、操作回放还是多 Agent 管理。
  - 用户是否愿意把回放结果发布成教程或内容。
- **风险：**
  - IDE 和 Agent 平台可能逐步内置类似能力。
  - 记录终端命令和文件内容会引发隐私与密钥泄露风险。
  - 用户可能觉得手动保存成本高，自动采集又会增加实现难度。
  - TrustMRR 的产品数据不能单独证明稳定市场需求。

## 反向视角

这件事可能不值得做，原因有四个：

1. 用户已经可以用 Git、聊天记录和 IDE 历史解决大部分问题，新增工具必须明显降低操作成本。
2. AI 编程用户不一定愿意为“记录过程”付费，他们可能只在出问题后临时寻找工具。
3. Termi Protocol 和 ClaudeKit 已经覆盖了相近需求，直接复制功能会缺乏差异化。
4. 本次证据没有提供独立的用户访谈、搜索需求、留存或付费转化数据，因此今天只能验证痛点，不能直接判断产品成立。

## 今天不要追

1. **BuilderPulse 的 build idea：** 本次数据源抓取失败，没有可用证据，不据此判断或选题。
2. **通用 AI 应用生成器：** AppGen 的产品描述明确，但方向过宽、竞争直接，且不如 AI 编程工作保护层适合在一周内做窄验证。
3. **泛 AI 视频生成平台：** Marc Lou 的案例说明了营销内容场景，但没有证明普通个人可以获得相同资源，也没有提供足够产品转化证据。
