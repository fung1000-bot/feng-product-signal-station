# 枫的产品信号站 - 2026-07-28

## 今日主判断

AI 编程的机会正在从“帮用户写代码”转向“直接交付可发布的结果”，但更适合枫当前验证的切口，仍是面向 AI 编程学习者和小微创业者的单点效率工具，而不是做通用 Agent 平台。

## 今日最值得做的一个方向

**项目名：** 中文场景 AI 表格任务助手

**面向谁：** AI 编程学习者、个人开发者、小微创业者，以及经常使用表格处理业务数据的人。

**解决什么具体问题：** 用户可以用自然语言描述表格任务，让工具直接生成公式、清洗数据、制作图表或完成基础分析，减少反复搜索公式和手工处理的时间。

**使用场景：**  
- “帮我把这一列手机号统一成标准格式。”  
- “根据销售额和成本计算毛利率。”  
- “找出重复客户并生成汇总表。”  
- “把这份数据做成按月份统计的图表。”

**为什么今天：**  
一方面，AI 编程工具正在降低从想法到可交付产品的门槛；另一方面，TrustMRR 上已经出现面向表格用户、能够产生收入的单点产品。与其追逐“全自动做 App”的宏大叙事，不如先验证一个边界清晰、两小时能做出原型的工作流。

**为什么适合枫：**  
它面向个人开发者、小微创业者和专业表格用户，用户问题容易被转化为 AI 编程实操内容。一个表格任务既可以做成产品验证，也可以拆成“小白如何用 AI 自动完成某个表格任务”的小红书或公众号选题。

**2 小时验证动作：**  
1. 做一个极简页面，只支持上传 CSV 或粘贴表格。  
2. 先实现三个任务：数据清洗、公式生成、简单汇总。  
3. 准备 10 个中文业务样例，例如销售表、客户表、内容选题表和收支表。  
4. 发布一个明确的招募帖：让目标用户提交一个最想自动化的表格任务。  
5. 记录用户提交的任务类型、是否愿意实际使用，以及是否愿意为节省时间付费。

**验证成功标准：**  
- 至少获得 5 个真实中文表格任务。  
- 至少 3 个任务能被原型正确处理或给出可执行结果。  
- 至少 2 位用户愿意再次使用。  
- 至少 1 位用户明确表示愿意为持续使用付费，或愿意提供下一份真实数据测试。

**周末能扩成什么：**  
扩展为“中文小微创业者业务表格助手”：增加模板库、任务历史、结果下载、常见中文字段清洗，以及针对小红书内容运营、客户管理和收入核算的预置任务。先保持单点工作流，不扩展成通用办公 Agent。

## 今日 Top 3 信号

### 信号 1

**信号类型：** 平台变化

**白话说：**  
AI 编程工具正在从“生成代码”向“替用户完成发布流程”发展。公开帖子声称，Codex 通过一次提示完成了一个新的 iOS App，并处理了应用描述、截图和上传提交流程；同时，阿里将多条 Agent 产品线整合为“千问办公”进行内测，说明办公 Agent 正在从零散工具走向统一入口。

**证据：**

- 来源 A：Marc Lou 描述 Codex 通过一次提示完成 iOS App、应用商店 listing、截图和上传提交，并获得 1,506 个赞、204,882 次曝光。[查看原始帖子](https://x.com/marclou/status/2081721767366967757)
- 来源 B：卡兹克称阿里将 QoderWork、悟空、MuleRun 三条 Agent 线整合为“千问办公”并开始内测。[查看原始帖子](https://x.com/Khazix0918/status/2081659248384020846)

**产品理解卡：** 不适用。

**为什么值得关注：**  
“会不会写代码”不再是唯一门槛，产品构建者需要重新理解需求验证、产品定位、发布和获客。工具越能自动完成交付，越值得把精力放在选择什么问题、如何获得真实用户和如何形成分发内容上。

**对枫的启发：**  
这是一个适合做内容的选题：“AI 编程现在能不能一条提示直接把 App 发布出去？”但不要只复述演示，应实际拆解完整链路：需求、代码、测试、商店资料、截图、审核和后续迭代分别还需要什么人工判断。

**反向证据：**  
目前证据主要是个人公开描述和互动数据，不等于稳定、普遍可复现的产品能力。帖子没有说明应用类型、失败次数、审核结果的具体时间，也没有证明普通用户能够用同样流程完成发布。

### 信号 2

**信号类型：** 产品案例

**白话说：**  
SheetAI 把自然语言表格操作直接放进网页端和 Google Sheets 插件中，目标不是教用户怎么写公式，而是在表格里直接完成公式生成、数据清洗、图表和分析。这是一个边界清晰、适合做中文垂直版本的产品案例。

**证据：**

- 来源 A：TrustMRR 产品页显示，SheetAI 面向 Google Sheets 和 Excel 用户，提供自然语言公式、数据清洗、图表和分析能力。[查看 TrustMRR 产品页](https://trustmrr.com/startup/sheetai)
- 来源 B：SheetAI 官网为其产品入口。[查看产品官网](https://sheetai.co/)

**产品理解卡：**  
- **它是什么：** 网站和 Google Sheets 插件形式的 AI 表格工具。  
- **目标用户：** 使用 Google Sheets 和 Excel 的专业用户。  
- **解决的痛点：** 表格工作耗时，用户往往不会写所需公式。  
- **核心功能或交付：** 用自然语言生成公式、清洗混乱数据、制作图表和分析文件，并直接在表格中工作。  
- **典型使用场景：** 公开证据未说明。  
- **已知商业数据：** TrustMRR 页面列示收入 $325、售价 $5k，具体数字以 [TrustMRR 原始页面](https://trustmrr.com/startup/sheetai) 为准；页面摘要另列月收入 $155，但两者口径未解释，不能直接合并使用。  
- **证据边界：** 公开资料没有说明用户数量、留存、主要获客渠道和中文市场需求，也没有证明其功能在复杂表格任务上稳定。

**为什么值得关注：**  
它同时满足“已有付费信号”和“可拆成窄 MVP”两个条件。相比做通用 AI 办公平台，中文版本可以先从一个具体人群和一组高频表格任务切入。

**对枫的启发：**  
可直接形成两类内容：  
1. 产品验证类：“我用 AI 编程做了一个中文表格助手，先解决 3 个任务。”  
2. 使用场景类：“不会写公式的人，如何让 AI 自动处理销售表/客户表/内容表？”

**反向证据：**  
表格 AI 已有成熟替代方案，包括 Excel、Google Sheets 原生能力、通用大模型和各种插件。若只是“把聊天框放进表格”，差异化不足；用户还可能担心数据隐私、公式错误和结果不可追溯。

### 信号 3

**信号类型：** 产品案例

**白话说：**  
Supamaus Lite 不是让 Agent 自己理解整个屏幕，而是让用户指出屏幕区域并用语音或文字补充意图，再把上下文发送给 Claude Code、Codex 或其他 MCP Agent。它解决的是“描述屏幕状态太麻烦”的交互问题。

**证据：**

- 来源 A：TrustMRR 产品页介绍 Supamaus Lite 可将用户指向的屏幕内容和语音直接发送给 Claude Code、Codex 或 MCP Agent，并强调设备端处理、不需要 API Key。[查看 TrustMRR 产品页](https://trustmrr.com/startup/supamaus)
- 来源 B：Supamaus Lite 产品官网。[查看产品官网](https://lite.supamaus.com/)

**产品理解卡：**  
- **它是什么：** 面向 AI Agent 的屏幕指向与上下文传递工具。  
- **目标用户：** 开发者、设计师、Vibe-coder、产品经理、创业者、写作者以及使用 Agent 的人。  
- **解决的痛点：** 用户不需要手动截图、复制粘贴或详细描述屏幕内容，就能把上下文交给 Agent。  
- **核心功能或交付：** 指向屏幕内容，配合语音或文字，将上下文发送给 Claude Code、Codex 或 MCP Agent；产品资料称其在设备端运行且不需要 API Key。  
- **典型使用场景：** 公开证据未说明。  
- **已知商业数据：** TrustMRR 页面列示收入 $374、售价 $28k，具体数字以 [TrustMRR 原始页面](https://trustmrr.com/startup/supamaus) 为准。  
- **证据边界：** 公开资料没有说明活跃用户数、留存、平台覆盖范围和实际工作流效果。

**为什么值得关注：**  
它说明 Agent 产品的机会不只在模型能力，也在于减少人和 Agent 之间传递上下文的摩擦。这个方向与 AI 编程学习者高度相关，但需要找到中文用户愿意持续使用的具体工作流。

**对枫的启发：**  
可以做一个低成本内容实验：演示“只圈出网页上的错误，再让编码 Agent 修复”，观察用户是否对“屏幕上下文交给 Agent”产生明确需求。若反馈集中在浏览器调试、报错解释或产品验收，可以再考虑做中文场景版本。

**反向证据：**  
屏幕共享、截图、OCR 和系统级辅助工具都能部分解决同一问题。Supamaus 的产品价值依赖用户高频使用 Agent；如果用户仍习惯复制错误信息和截图，额外安装一个工具的必要性可能不够强。

## 机会拆解

- **痛点：** 中文用户处理业务表格时，经常需要清洗字段、写公式、汇总数据，但不一定具备表格函数能力。  
- **明确买家：** 小微创业者、内容运营者、个体经营者、AI 编程学习者和需要快速处理业务数据的专业用户。  
- **已有替代：** Excel、Google Sheets、通用大模型、现有表格插件和人工处理。  
- **小产品入口：** 不做通用办公 Agent，先做“中文表格任务执行器”，只支持粘贴或上传数据，并优先解决三类高频任务。  
- **可验证数据：** 用户提交的真实任务数量、任务成功率、重复使用率、愿意提供真实数据测试的人数、愿意付费的人数。  
- **风险：** 表格数据可能包含隐私信息；AI 生成的公式或清洗结果可能出错；中文用户是否愿意安装插件或上传文件尚未验证；现有产品可能已经覆盖大部分基础需求。

## 反向视角

这件事可能不值得做，原因包括：

1. 表格 AI 已经是明确存在的产品类别，简单复刻功能未必有足够差异。  
2. TrustMRR 的收入和售价是公开市场条目中的资料，不代表产品的收入质量、留存或可复制性。  
3. 中文用户可能更愿意直接把表格问题发给通用大模型，而不是使用专门工具。  
4. 如果用户最在意的是数据安全，纯在线 MVP 会遇到信任障碍。  
5. 当前 AI 编程工具的端到端能力可能快速提升，单纯做“帮用户写公式”的产品容易被平台能力覆盖。

因此，第一步不应是完整开发，而应是收集真实表格任务，验证用户是否愿意反复使用，以及哪些任务值得做成专用工作流。

## 今天不要追

1. **BuilderPulse 的 build idea**：本次抓取失败，没有可验证的当日报告证据，不据此做判断。  
2. **通用 AI App 自动发布平台**：虽然端到端 Agent 话题热度高，但当前证据不足以证明普通用户可稳定复现，且平台依赖和审核流程风险较高。  
3. **需要大量内容投放或账号运营的增长工具**：当前更适合先积累真实产品验证和实操选题，不把核心方向放在代运营或纯平台号上。
