# 枫的产品信号站 - 2026-07-27

## 今日主判断

最值得验证的不是又一个通用 AI 应用，而是“让 AI 编程代理更容易看懂屏幕和上下文”的轻量工具：Supamaus 负责捕捉视觉上下文，Headroom 负责压缩输入成本，两者共同指向 AI 编程实操中的即时痛点。

## 今日最值得做的一个方向

**项目名：** 面向 AI 编程代理的中文屏幕上下文采集器

**面向谁：**

使用 Claude Code、Codex 或其他 AI Agent 的个人开发者、Vibe-coder 和小微创业者。

**解决什么具体问题：**

用户在调试网页、桌面软件或复杂操作流程时，需要反复截图、描述问题、复制日志，再粘贴给 AI。产品把“我指向哪里 + 我说了什么”直接整理成可发送给 AI 的上下文，减少手工描述。

**使用场景：**

- 指向网页上的报错区域，让 AI 判断问题。
- 指向某个按钮或布局，要求 AI 修改对应页面。
- 截取桌面软件状态，连同语音说明发送给 Claude Code、Codex 或 MCP Agent。
- 将截图、选区、语音和当前任务合并成一段结构化提示词。

**为什么今天：**

TrustMRR 中的 Supamaus 已验证了一个明确方向：用户愿意为“把屏幕上下文直接交给 AI Agent”支付一次性费用；Headroom 则说明 Claude Code 和 Codex 用户还在意输入膨胀与额度消耗。今天可以把两个痛点合并成一个中文市场验证题，而不是从完整桌面应用开始。

**为什么适合枫：**

它直接面向 AI 编程学习者和个人开发者，用户容易通过小红书、公众号和开发者社群触达。MVP 可以先做浏览器扩展或截图上传网页，不需要囤货、物流或重资产投入，也不依赖爬取敏感数据。

**2 小时验证动作：**

1. 做一个最小网页工具：用户上传截图，框选区域并输入一句话。
2. 调用现有视觉模型，将截图区域、用户描述和页面目标整理成适合 Claude Code/Codex 的提示词。
3. 输出三种格式：复制提示词、复制 Markdown、下载 JSON。
4. 发布一篇实测内容：《我做了一个让 AI 直接看懂报错截图的小工具》。
5. 在 AI 编程学习者社群或内容评论区邀请 5 人试用，观察他们是否愿意提交第二个真实问题。

**验证成功标准：**

- 至少 5 人完成一次真实问题提交。
- 至少 3 人表示减少了手工描述或复制粘贴。
- 至少 2 人主动提出继续使用、接入 Claude Code/Codex 或增加语音功能。
- 至少 1 人愿意为长期使用支付小额费用，或明确表示愿意进入候补名单。

**周末能扩成什么：**

扩展为中文 AI 编程上下文助手：支持浏览器选区、屏幕截图、语音说明、终端日志整理、提示词模板和 MCP/剪贴板交付。先验证“上下文整理”是否有价值，再决定是否做桌面端常驻工具。

## 今日 Top 3 信号

### 信号 1

**信号类型：** 产品案例

**白话说：**

AI Agent 越来越能写代码，但用户仍然需要手动告诉它“屏幕上发生了什么”。Supamaus 的切入点不是训练新模型，而是把人眼看到的内容更快交给 Agent。

**证据：**

- 来源 A：[Supamaus — TrustMRR 产品页](https://trustmrr.com/startup/supamaus)：产品描述为让 AI Agent 看见屏幕并执行操作；Supamaus Lite 将用户指向的内容和语音直接发送给 Claude Code、Codex 或 MCP Agent，价格为 $15 一次性购买。
- 来源 B：[Marc Lou 关于 TrustMRR 新增 App Store/Play Store 验证指标的说明](https://x.com/marclou/status/2081398389611323668)：说明 TrustMRR 正在补充移动应用的商店评级等验证信息；但该条没有单独证明 Supamaus 的移动端表现。

**产品理解卡：** Supamaus  
- **它是什么：** 面向 AI Agent 的屏幕上下文采集工具。  
- **目标用户：** Developers、Designers、Vibe-coders、PMs、founders、writers 以及使用 Agent 的用户。  
- **解决的痛点：** 用户不必手动复制、粘贴或描述屏幕内容。  
- **核心功能或交付：** 在设备端捕捉用户指向的屏幕内容和语音，并发送给 Claude Code、Codex 或 MCP Agent；不需要 API Key。  
- **典型使用场景：** 公开证据未说明。  
- **已知商业数据：** TrustMRR 页面记录收入 $391，产品价格为 $28k，倍数 6.0x；[TrustMRR 原始链接](https://trustmrr.com/startup/supamaus)。Supamaus Lite 标价 $15 一次性购买。  
- **证据边界：** 页面没有说明用户数量、留存、具体使用频率或典型场景；TrustMRR 商业数据不能单独证明利润质量。

**为什么值得关注：**

这是一个非常适合单人快速验证的“输入层”产品。它避开了训练模型和构建完整 Agent 的高成本，直接改善 AI 编程过程中的一个高频摩擦点。

**对枫的启发：**

- **产品机会：** 先做“截图/选区 → 中文结构化提示词”，不要一开始复制完整桌面端。
- **内容选题：** “为什么 AI 看不懂你的报错截图”“我把截图变成 Codex 能直接执行的任务”。
- **风险提醒：** 屏幕内容可能包含隐私、Token、密码和客户数据，必须默认本地处理或明确脱敏。

**反向证据：**

用户可能已经习惯系统截图、剪贴板和直接上传图片给模型；如果中文工具只多了一层包装，付费意愿可能很弱。Supamaus 的收入数字也没有提供用户数和留存，不能据此判断市场规模。

### 信号 2

**信号类型：** 产品案例

**白话说：**

AI 编程工具的另一个痛点不是模型不够强，而是上下文太长、工具输出太杂，导致额度消耗快。Headroom 的做法是压缩输入，而不是更换模型。

**证据：**

- 来源 A：[Headroom — TrustMRR 产品页](https://trustmrr.com/startup/headroom)：产品针对 Claude Code 和 Codex，压缩提示词、工具输出、日志和模板内容，主张降低约 50% 的使用成本。
- 来源 B：[刘小排关于 Opus 5 与 GPT-5.6 Sol 使用体验的讨论](https://x.com/bourneliu66/status/2081269376700015070)：用户已经在比较不同模型处理复杂后端逻辑和长程任务的能力，说明模型选择与上下文成本是实际工作流问题。

**产品理解卡：** Headroom  
- **它是什么：** 面向 Claude Code 和 Codex 的输入优化与压缩工具。  
- **目标用户：** 使用 Claude Code 或 Codex 的开发者。  
- **解决的痛点：** 噪声提示词、冗长工具输出和日志消耗使用额度，迫使用户减少使用或支付更多费用。  
- **核心功能或交付：** 在菜单栏中压缩工具输出、日志、文档和模板，同时尽量保留信息。  
- **典型使用场景：** 公开证据未说明。  
- **已知商业数据：** TrustMRR 页面记录收入 $2.8k，产品价格为 $98k，倍数 2.9x；[TrustMRR 原始链接](https://trustmrr.com/startup/headroom)。价格方案包括免费版、$3/月 Pro、$12/月 Max x5 和 $24/月 Max x20。  
- **证据边界：** “降低约 50%”是产品描述中的主张；输入压缩是否影响模型准确率、不同项目的实际节省比例，公开证据未说明。

**为什么值得关注：**

它把“AI 编程成本”从抽象的模型价格，转化为用户每天都能感受到的上下文管理问题。这个方向比单纯做模型评测更接近可付费的工作流改进。

**对枫的启发：**

- **产品机会：** 做一个中文版本的“AI 编程上下文清理器”，先处理终端日志、重复报错、无关依赖信息。
- **内容选题：** “为什么你的 Claude Code 额度消耗这么快”“同一个任务，压缩上下文前后有什么区别”。
- **验证方式：** 不必先做常驻菜单栏应用，可以先做命令行或网页工具，比较原始提示词和压缩后的 Token 数量及任务结果。

**反向证据：**

压缩上下文存在丢失关键信息的风险；高级用户可能自己维护提示词模板或直接换更大套餐。若无法证明准确率不下降，用户不会为了节省额度承担调试失败成本。

### 信号 3

**信号类型：** 平台变化

**白话说：**

今天最适合做内容的 AI 编程话题有两个：一是不同模型在真实复杂任务中的能力差异，二是 Claude Code 相关优惠或漏洞引发的账号与合规风险。后者可以作为风险提醒，不能作为产品机会或操作教程。

**证据：**

- 来源 A：[刘小排关于 Opus 5 使用体验的讨论](https://x.com/bourneliu66/status/2081269376700015070)：其公开观点是 Opus 5 在多数能力上优于 Fable 5，但不一定全面超过 GPT-5.6 Sol；复杂后端逻辑和长程任务存在差异。
- 来源 B：[刘小排关于 Claude Code 订阅漏洞的讨论](https://x.com/bourneliu66/status/2081300898308104530)：公开内容提到 Claude Code 出现订阅漏洞及低价中转站折扣，但这属于未经授权的优惠/漏洞线索，不应作为验证方向。

**产品理解卡：** 不适用。

**为什么值得关注：**

AI 编程用户不再只关心“哪个模型最强”，而是关心不同模型在具体任务中的表现、成本和稳定性。这可以直接转化为低粉账号的实测型内容，而不是泛泛发布模型新闻。

**对枫的启发：**

- 做“同一需求分别交给 Opus 5、GPT-5.6 Sol 和其他工具”的任务实测。
- 记录复杂后端、长程修改、上下文消耗和返工次数，形成可复用的评测模板。
- 关于订阅漏洞，只做“不要使用来路不明的优惠和中转服务”的风险提醒，不复现、不传播关键词、不引导绕过付费。

**反向证据：**

这组模型比较来自单一公开讨论，样本很小，且缺少可复现任务、成本记录和独立测评。漏洞类话题可能带来短期流量，但无法形成合规、稳定的产品方向。

## 机会拆解

- **痛点：** AI 编程用户需要把屏幕、截图、日志和语音说明整理成 Agent 可执行的上下文，同时还受到上下文长度和额度成本影响。
- **明确买家：** 高频使用 Claude Code、Codex 或其他 Agent 的个人开发者、Vibe-coder、小型创业团队。
- **已有替代：** 系统截图、直接上传图片、剪贴板、手写提示词、终端日志复制，以及模型自带的视觉能力。
- **小产品入口：** 截图/框选区域 + 中文描述 → 结构化提示词；第二步再加入日志压缩和语音输入。
- **可验证数据：** 完成真实问题提交的人数、重复使用率、生成提示词被直接复制到 Agent 的比例、用户主观节省时间、愿意支付的价格。
- **风险：** 屏幕隐私和密钥泄露、视觉模型调用成本、压缩导致信息丢失、与 Claude Code/Codex 接口变化、用户认为系统截图已经足够。

## 反向视角

这件事可能不值得做，原因有四个：

1. ChatGPT、Claude Code、Codex 可能持续增强截图和屏幕理解能力，独立采集层容易被内置功能替代。
2. 用户真正的痛点可能不是“看不见屏幕”，而是需求不清楚、代码库复杂或 Agent 执行能力不足。
3. Supamaus 和 Headroom 的公开商业数据不足以证明中文市场存在同等付费意愿。
4. 如果产品需要上传完整屏幕，隐私风险会抵消便利性；如果坚持本地处理，技术实现和跨平台成本又会上升。

因此，今天只验证“中文结构化上下文是否比直接上传截图更有用”，不要直接开发完整桌面应用。

## 今天不要追

1. **Claude Code 订阅漏洞、低价中转站和绕过付费**：涉及授权、账号安全和平台规则风险，不能作为产品方向。
2. **完整 AI Website Builder**：TrustMRR 中该产品规模和运营成本明显高于一人一周 MVP 的范围，且公开证据没有官网和完整定价信息。
3. **社交匹配、婚礼视频剪辑等非目标领域产品**：Locale 和 Weddx 有明确产品形态，但与当前 AI 编程受众和枫的内容获客路径连接较弱，暂不优先。
